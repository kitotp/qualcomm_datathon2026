**Какие данные получает модель**

В исходных JSONL есть условие и частично распознанные варианты ответа. При пустом
`options` текстовой модели недостаёт вариантов; рисунков в JSONL тоже нет.
Поэтому для этого эксперимента экспортированы исходные изображения из parquet M3Kang.
На каждом изображении находятся условие, варианты и рисунок, если он нужен.
Модель получает полное изображение и одинаковую инструкцию. Нет фильтра по наличию
OCR-вариантов или рисунка, нет подстановки ответа из другого метода.

Разрешение ограничено 384 визуальными токенами: пропорциональное уменьшение,
без обрезки. Одинаковый процессор и prompt используются до и после обучения.
`label`, язык, уровень, `text_only` и разбиение не передаются в prompt.

**Обучение и выбор модели**

База: `mlx-community/Qwen3-VL-2B-Instruct-4bit`, revision
`9c4f5209e57b31f4b9dfba735de3fb983739c9cc`.
В отличие от использовавшегося ранее текстового пути Gemma 1B, этот путь получает
непосредственно пиксели, включая графические варианты ответа.

- LoRA на q/k/v/o проекциях последних 8 из 28 языковых слоёв.
- Rank 8, alpha 16, фактический scale 2, dropout 0; 917 504 обучаемых параметра.
- Визуальный encoder, первые 20 языковых слоёв и embedding заморожены.
- Их выходы кешируются в исходной точности. Проверена эквивалентность с полным
  проходом, в том числе после изменения LoRA и сохранения/загрузки: максимальная
  разница проверенных A–E logits — 0,0.
- Loss: cross-entropy только среди следующих токенов A–E; служебные токены в loss
  не входят. На inference применяется тот же argmax среди A–E.
- AdamW, learning rate 5e-5, warmup 5%, cosine decay до 1e-5, clipping 1.
- Планировались максимум три эпохи, batch 8, seed 42. Завершены две полные эпохи;
  каждый train-пример использован в каждой из них. Третья эпоха началась, но её
  незавершённые обновления отброшены после решения о ранней остановке.
- Сохраняются все эпохи; выбирается первая с максимальной accuracy на internal dev.
  Отдельно фиксируется, если исходная модель на dev лучше обученных checkpoint.

| Checkpoint | Internal dev | Постоянный ответ D на том же dev |
|---|---:|---:|
| Исходная модель | 38/292 = 13,01% | 84/292 = 28,77% |
| Эпоха 1, шаг 329 — выбран | 85/292 = 29,11% | 84/292 = 28,77% |
| Эпоха 2, шаг 658 | 84/292 = 28,77% | 84/292 = 28,77% |

Преимущество лучшего checkpoint над постоянным D — одна строка dev.
Вторая эпоха не улучшила результат. По условию пользователя не продолжать
бесполезные запуски выполнена ранняя остановка; третья эпоха не оценивалась и
не использовалась. Последний записанный тренировочный шаг — 670; выбранные
для полной validation веса сохранены на шаге 329 и от этого не меняются.
Это остановка контроллером эксперимента, а не ошибка градиентов или нехватка памяти.

Это обучение выбору ответа по изображению. В M3Kang нет эталонных решений или
разбора ошибок ученика. Даже улучшение accuracy само по себе не подтверждает,
что свободное объяснение модели корректно.

Диагностические четыре шага на четырёх train-примерах уменьшили loss с 3,70 до 0,60.
Эта проверка подтверждает прохождение градиентов и работоспособность сохранения;
это не результат на validation и не доказательство обобщения.

**Воспроизведение на Apple Silicon**

Версии окружения зафиксированы в `requirements-vlm.lock.txt`. Это отдельное host-
окружение; зависимости не добавлены в код для платы.

```bash
uv venv --python 3.12 .venv-vlm
uv pip sync --python .venv-vlm/bin/python requirements-vlm.lock.txt

# Существующий локальный parquet high_quality-00000-of-00004.parquet.
.venv-vlm/bin/python tools/prepare_multimodal.py --parquet /path/to/source.parquet
.venv-vlm/bin/python -u tools/cache_multimodal.py
.venv-vlm/bin/python -u tools/train_multimodal.py --epochs 3 --patience 1
.venv-vlm/bin/python -u tools/eval_multimodal.py \
  --adapter models/m3kang-vision-lora/best --out results/multimodal/after-val
.venv-vlm/bin/python tools/report_multimodal.py
```

Кеш содержит выходы замороженных слоёв для исходного изображения; он не содержит
сгенерированного решения или подставленной правильной буквы. При изменении базы,
prompt, разрешения или замороженных слоёв нужен новый кеш.

В первом запуске остановка была выполнена внешним контроллером после чтения dev
эпохи 2. В код добавлен `--patience 1`, чтобы последующий запуск останавливался
автоматически при первом отсутствии улучшения dev. Максимум `--epochs 3` нужно
сохранить: от него зависит расписание learning rate и до ранней остановки.

Inference после завершения обучения, без сети и без правильной метки на входе:

```bash
.venv-vlm/bin/python tools/predict_multimodal.py \
  --image /path/to/problem.jpg --output results/one-image.csv
```

Для нескольких изображений `--input` принимает JSONL с `id`, `language`,
`image_path`. Поля `label` не нужны и не используются при предсказании.
При ошибке обработки эксперимент возвращает явный статус ошибки и пустой ответ;
в оценке такой пример остаётся в знаменателе и считается неправильным.

Рабочие артефакты: `models/qwen3-vl-2b-4bit` плюс
`models/m3kang-vision-lora/best`. Картинки, features, веса и сырые результаты
не коммитятся. Исходные `predict.py` и пайплайн платы этим экспериментом не заменены.
MLX-адаптер сам по себе не является сборкой для UNO Q: экспорт, работа с изображением
на плате, её память и ограничение 60 секунд должны проверяться отдельно.
