**Qwen3-VL 2B: решение перед буквой, 15 ноября 2026**

**Результат: полезного преимущества в проверенных режимах не получилось.
Обучение не запускалось.** Проверены одни и те же 50 уникальных задач internal dev.
Это не новая accuracy на полной validation из 562 строк.

| Режим | Правильно на тех же 50 задачах | Достигнут лимит решения |
|---|---:|---:|
| Сразу буква, argmax A–E | 7/50 = 14% | Не применяется |
| Сначала решение, температура 0, затем буква | 13/50 = 26% | 41/50 |
| Сначала решение, sampling 0,7, затем буква | 10/50 = 20% | 40/50 |
| Постоянный ответ D | 17/50 = 34% | Не применяется |

Первый режим рассуждений добавил 7 правильных ответов и потерял 1 относительно
прямой буквы: чистая разница +6. Sampling добавил 6 и потерял 3: чистая разница +3.
Оба режима уступили постоянному D. Эти результаты не обосновывают новый fine-tune
или долгий прогон основной validation. По условию пользователя не продолжать
бесполезные запуски дальнейшие эксперименты и обучение не запущены.

**Что именно проверено**

- Исходная `mlx-community/Qwen3-VL-2B-Instruct-4bit`, revision
  `9c4f5209e57b31f4b9dfba735de3fb983739c9cc`, без обученного ранее LoRA.
- Полное изображение: условие, варианты, рисунок. Пропорциональное уменьшение
  с бюджетом 384 визуальных токена, такое же, как в предыдущем эксперименте.
- Максимум **768 генерируемых токенов решения** — отдельный от изображения бюджет.
- Фиксированная выборка до запуска: seed `20261115`, уникальные ID из internal dev,
  обход уровней по очереди до исчерпания доступных ID, чередование языков.
  Правильные буквы, успешность OCR и результат модели не используются при отборе.
- 25 английских и 25 каталанских примеров; 26 `text_only`, 24 с рисунком.
  Один перевод каждого выбранного ID, а не два перевода одной задачи.
- Второй режим использует параметры из локального `generation_config.json`:
  temperature 0,7, top_p 0,8, top_k 20. Seed генерации для строки — `20261115 + index`.
  Это один фиксированный seed, а не лучший из нескольких запусков.
- После собственного решения **для каждого** примера модель получает одинаковый
  дополнительный запрос буквы. Берётся argmax A–E. Это не внешнее правило, не
  ответ из датасета и не подстановка прежнего метода при неудаче.
- Все 50 примеров включены в каждый знаменатель. Ошибок обработки: 0 в обоих
  режимах. Незавершённые решения не удаляются.

Первоначальный короткий пилот с 384 генерируемыми токенами был остановлен после
обнаружения обрыва решения. Его файлы сохранены отдельно как `pilot384.*`.
В обеих таблицах основного сравнения используется один бюджет 768 и одна выборка.

**Формат ответа и незавершённые решения**

Самостоятельную строку `Final answer: X` удалось извлечь в 9/50 случаев при
температуре 0 и 10/50 при sampling. Если считать только явно записанную финальную
букву, оставляя отсутствие строки неправильным ответом, результат составляет
соответственно **8/50 и 7/50**. Нельзя выдавать 8 правильных из 9 завершённых
ответов за accuracy на всех задачах.

После дополнительного запроса распределение букв:

| Режим | A | B | C | D | E |
|---|---:|---:|---:|---:|---:|
| Решение, температура 0 | 39 | 2 | 6 | 3 | 0 |
| Решение, sampling | 38 | 2 | 6 | 2 | 2 |

Смещение к A сохранилось. Большой объём текста не стал надёжным решением.
Достижение лимита само по себе не доказывает повтор: повторы и ошибки условий
проверены отдельно на десяти примерах ниже.

**Проверки и время**

Прямые ответы обоих прогонов сверены с сохранёнными ответами исходной модели
на тех же dev-строках: совпадают. ID, языки и метки совпадают между режимами;
выборки основного опыта и пилота совпадают. Проверено отсутствие пересечения ID
выбранных задач с train и основной validation.

Для `lvl-5_2023_3`, cat, sampling повторён после свежей загрузки модели без
предшествующего прямого запроса. При том же seed получен **точно тот же текст**,
включая 768 токенов и повторы. Для этого случая перенос состояния между запросами
не объясняет вырождение. Это одна проверка; устойчивость качества между разными
seed не исследовалась.

На Apple M3 прямой ответ занял около 0,9 с. Решение с дополнительным запросом
буквы: в среднем 11,84 с при t=0 и 13,28 с при sampling. Полные парные прогоны:
637,25 с и 709,78 с. Это диагностические замеры на Mac; короткая проверка свежей
загрузки выполнялась параллельно части sampling-прогона. Строгое сравнение
производительности и ограничение 60 секунд на UNO Q здесь не проверены.

**Воспроизведение и артефакты**

Окружение — прежнее `.venv-vlm`, версии в `requirements-vlm.lock.txt`.
Все изображения и базовая модель уже локальные, API и новое обучение не используются.

```bash
.venv-vlm/bin/python -u tools/bench_multimodal_reasoning.py \
  --n 50 --seed 20261115 --max-tokens 768 --temperature 0 \
  --out results/vision-reasoning/dev50
.venv-vlm/bin/python -u tools/bench_multimodal_reasoning.py \
  --n 50 --seed 20261115 --max-tokens 768 --temperature 0.7 \
  --out results/vision-reasoning/dev50-sampling
```

Для каждого режима сохранены `*.sample.json` с фиксированными ID и параметрами,
`*.jsonl` с полными ответами и статусами, `*.summary.json` с метриками.
Ручной разбор — `results/vision-reasoning/audit-ten.json`, проверка свежей загрузки —
`independence-check.json`. Сырые задачи, рассуждения и изображения не коммитятся.
Рабочий `predict.py`, веса и код пайплайна платы не изменены.

Предыдущий [fine-tune по изображениям](VISION_FINETUNE_RESULTS.md) — другой
эксперимент. Его числа на 562 строках нельзя непосредственно сравнивать с
процентами этой диагностической выборки из 50 задач.
